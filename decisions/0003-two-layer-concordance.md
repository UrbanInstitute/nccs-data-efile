# 0003 — Phase 0.5 Build: NCCS-Owned Two-Layer Concordance

- **Status:** Accepted; executed 2026-06-09 (Layer 1 S3 republish + nccs-contracts reconcile pending — see Open items)
- **Date:** 2026-06-09
- **Deciders:** sole maintainer
- **Inherits from:** [[0001-producer-design]], [[0002-phase-0-pri-gov-grants-slice]]
- **Inherits from (nccs-contracts):** [[0017-efile-phase-0-vertical-slice]] (§3 is the mandate for this work), [[0007-efile-urban-owned-producer]], [[0014-standardize-manifest-shape]]

## Context

`nccs-contracts/decisions/0017` §3 set the Phase 0.5 mandate: transition
from extracting against a *vendored* NODC concordance to an
**NCCS-owned, two-layer concordance**, after which NODC drops from a
build input to an automated *comparison artifact*. Phase 0 ([[0002]])
shipped two fields by resolving XPaths from a hand-maintained
`config$xsd$phase0_claims` list and a small dictionary, with NODC pinned
at a SHA as the source those claims were derived from.

What 0017 §3 fixed was the *target architecture* (two layers, NODC as
comparison artifact). What it did not pin was the *build*: which
components, in what order, how verification is wired, and what counts as
"done" for Phase 0.5. This ADR is that record. It is deliberately scoped
to the concordance machinery; widening the extracted field set is
Phase 1+ ([[0017]] roadmap), and any move to a wholesale/quick-extract
model would be a separate ADR amending 0007/0017 (not undertaken here —
Phase 0.5 stays within the curated, demand-driven framing).

## Decision — the two-layer architecture

**Layer 1 — mechanical XSD inventory.** A full enumeration of every
element reachable from the in-scope form roots in each IRS XSD bundle,
one row per `(tax_year, version, xpath)` with parent path, declared XSD
type, cardinality, leaf-ness, and any `xsd:documentation`. Generated by
a depth-first walk (`build_xsd_inventory()` in `R/xsd_inventory.R`),
**never hand-edited**, regenerated per IRS schema release. It is the
inverse traversal of the old verifier: that resolved a *known* path
top-down; this enumerates *all* paths. Roots for Phase 0.5 are
**990 + 990PF + ReturnHeader** (the walker is form-agnostic; widening to
schedules/990EZ is a `default_inventory_roots()` change for Phase 1+).
`build_all_xsd_inventories()` runs the configured `(year, version)`
cross-product; `publish_xsd_inventory()` writes a consolidated parquet +
provenance manifest to `s3://nccsdata/processed/efile/concordance/layer1/{date}/`
(with a `latest/` mirror).

**Layer 2 — curated semantic dictionary.** The existing
`inst/concordance/nccs_dictionary.csv` (structure unchanged from
[[0002]]): NCCS `snake_case` names → `(tax_year, version, xpath)` claims
+ IRS-instruction citations. Phase 0.5 promotes it from "the thing the
extractor reads" to **the single source of truth that drives schema
verification** — there is no longer a parallel `phase0_claims` list to
keep in sync.

**The unified schema gate.** `run_phase0_verification()` now builds
Layer 1 once and verifies Layer 2's own claims against it via
`verify_dictionary_against_inventory()`, then shapes the result into the
manifest's `xsd_verification` block (**same shape** — no contract
change). Each claim must resolve to a **leaf** element whose XSD type is
consistent with the field's `data_type` (numeric `double`/`int` → a
numeric XSD type, hard failure; non-numeric data_types recorded, not yet
enforced). This replaced the per-claim live XSD re-walk and retired
`config$xsd$phase0_claims`. `verify_xpath()` survives as the single-cell
inventory-lookup primitive.

**NODC as comparison artifact.** `compare_dictionary_to_nodc()`
(`R/compare_nodc.R`) is an informational, non-blocking diff of Layer 2
against the *full* NODC concordance — agreement / divergence / broken
link, plus a coverage figure. NODC stays vendored at a pinned SHA for
provenance and `drift_check_nodc()` still flags upstream changes, but
correctness is now established by NCCS's own checks against the IRS XSDs
(Layer 1), not by trusting NODC.

**Version normalization.** All cross-layer joins normalize version
strings via `canon_version()` (dotted vs the hyphenated IRS folder
convention) — the `5-0`-vs-`5.0` split that nulled TY2022/2023 in
v2026.05 ([[0002]] Outcome). Gated schemas with no public XSD
(2024 v5.1/v5.2, 2023 v6.0) inherit the nearest published version via
`config$xsd$version_aliases`, recorded in the manifest.

## Acceptance criteria — "Phase 0.5 is done" when:

1. Layer 1 builds for every in-scope `(tax_year, version)` cell and is
   published to S3 with a provenance manifest. **Met.**
2. Layer 2's claims are verified against Layer 1 (existence + leaf +
   type) and that gate is wired into the build, retiring
   `phase0_claims`. **Met.**
3. NODC is demoted to an informational comparison artifact. **Met.**
4. No regression: published outputs and the manifest's
   `xsd_verification` shape are unchanged. **Met** (v2026.06 outputs
   unaffected; shape preserved).
5. `nccs-contracts` 0017 §3 reflects executed Phase 0.5. **Pending.**

## Outcome (2026-06-09)

Shipped across five PRs, all merged to `main`:

| PR | Merge | What |
|---|---|---|
| #6 | `48b20f0` | Layer 1 walker + driver + S3 publish (`R/xsd_inventory.R`) |
| #7 | `e005e26` | Layer 2 ↔ Layer 1 gate (`R/verify_dictionary_inventory.R`) |
| #8 | `6f2528e` | `2023v6.0` schema alias (config) |
| #9 | `ff5cbfc` | NODC comparison artifact (`R/compare_nodc.R`) |
| #11 | `534b879` | Inventory-backed schema gate; retire `phase0_claims` |

**Layer 1.** 23,699 rows over 16 `(year, version)` cells (14 real XSD
dirs + 2024 v5.1/v5.2 + 2023 v6.0 aliased), 0 cycle/depth truncations,
22,611 rows carrying IRS `xsd:documentation`. Correctness check: the
walker independently rediscovers both Phase-0 anchors
(`GovernmentGrantsAmt`, `SumOfProgramRelatedInvstGrp/TotalAmt`) at the
right paths with `USAmountType` / `is_leaf=TRUE`.

**The gate, live.** 34/34 dictionary claims verify against Layer 1, 0
mismatches; the manifest's `mismatches` list dropped from ~80
dead-variant rows (under the old `phase0_claims` re-walk) to 0. Net
**−332 lines** when the redundant verifier was unified.

**Findings the build surfaced (worth recording):**

- **`2023v6.0` gap.** The L2↔L1 gate flagged the dictionary's `2023:6.0`
  claims as `unverifiable_no_cell` — TY2023 filings declare
  `returnVersion` 6.0 but the IRS publishes no 2023v6.0 schema. Resolved
  by aliasing 2023v6.0 → 2023v5.1 XSDs (PR #8), mirroring the 2024
  v5.1/v5.2 → v5.0 pattern. The gate then reads 34/34.
- **NODC is split and dual-keyed.** The root `concordance.csv` covers
  Form 990 (PC) and keys on `variable_name`; Form 990-PF lives in
  per-part files under `02-concordance-foundations/` and adds a
  `variable_name_new` column. `load_nodc_concordance()` unions both
  (9,081 rows / 20 files) and the comparison matches on **both** name
  columns; coverage counts distinct *logical* variables (≈3,246) by
  coalescing the old/new aliases. Loading only the root made every PF
  field look absent.
- **Type rigor moved from a literal to a class.** Retiring
  `phase0_claims` removed its per-field `expected_type = "USAmountType"`
  literal. Rather than couple Layer 2 to XSD type names, the gate
  asserts a mechanical **type-class** match (numeric `data_type` → a
  numeric XSD type). Preserves the rigor for the two `double` fields and
  scales without per-field maintenance.

## Open items

1. **Republish Layer 1 to S3** to include the 2023v6.0 cell — the
   published artifact predates the alias (PR #8). The build's gate is
   unaffected (it rebuilds the inventory from the XSD cache), so this is
   a freshness fix for the published reference, not a correctness fix.
2. **Widen inventory roots** to schedules / 990EZ before Layer 2 claims
   any field on them (a claim on an un-enumerated form reads as
   `missing_xpath`).
3. **Type-class enforcement for non-numeric data_types** (string /
   bool / date) — recorded but not enforced until Layer 2 has such
   fields.
4. **Reconcile `nccs-contracts` 0017 §3** to executed Phase 0.5.

## Consequences

**Positive.** A single, mechanical source of XSD truth; the dictionary
is now self-verifying against ground truth, so a typo'd or renamed XPath
is an unrepresentable build state rather than a silent stream of NAs.
NODC dependence is reduced to provenance + an informational cross-check.
The unified gate is faster (one inventory build vs a per-claim re-walk)
and simpler (one list to maintain, not two).

**Negative.** Verification coverage is now bounded by the inventory's
root scope — a correctness property that used to be implicit (the XSD
held everything) is now an explicit thing to maintain (`open item 2`).
The non-numeric type check is deferred, so a future non-numeric field
ships without the type rigor the numeric fields enjoy until the
allowlist is extended.
